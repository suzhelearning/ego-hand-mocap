# EGO 联合采集：两种方法

本项目联合采集入口仅提供两种互斥模式，均由 Ubuntu 发起，均将 EGO 原始 H5、视频及元数据导出到 Ubuntu。

| 模式 | 动捕保存位置 | 是否控制 Motive 录制 |
|---|---|---|
| `h5` | Ubuntu 的 `mocap.h5` | 否；接收已开启的实时流 |
| `take`（默认） | Windows 指定目录中的 Motive 原生 Take | 是；切换 Live，开始、停止并核验 Take |

没有同时生成 Ubuntu 动捕 H5 与 Windows Take 的第三种模式。Take 模式接收 NatNet 帧仅用于实时状态检查，不写动捕 H5。

## 方法一：EGO + Ubuntu H5

Motive 需提前打开并进入 Live，开启 NatNet 数据流，至少有一个刚体可见。在项目目录执行：

```bash
./mocap record --mode h5 --session-id hand_h5_001
```

H5 模式需显式指定 `--mode h5`。定时录制可加 `--duration 5`。

程序开启 Ubuntu 动捕保存，再请求 EGO 开始录制。停止时先停 EGO，再保存少量动捕尾帧。该模式不会发出 Motive 的开始或停止录制命令。

## 方法二：EGO + Windows Take（默认）

直接运行 `./mocap record` 即选择此模式。

Motive 必须已经打开，相机、标定和跟踪资产配置就绪，NatNet 数据流开启；录制开始前不得已有其他 Take 正在录制。

```bash
./mocap record --mode take \
  --session-id hand_take_001
```

默认保存根目录为 Windows SSH 登录用户的 `~/Desktop/syz/ego-hand/remote`（通常为 `C:\Users\<用户名>\Desktop\syz\ego-hand\remote`），由远端查询用户目录，不使用 Ubuntu 的 `~`。可通过 `--windows-take-root 'D:\MocapSessions'` 覆盖为 Windows 绝对路径。Bash 中请使用单引号包住反斜杠路径。Windows 根目录需允许 Motive 用户和 SSH 用户读写。目录名称不能含逗号、换行或通配符。

执行流程：

1. 检查 EGO 空闲，通过 NatNet 命令确认或切换 Motive Live 模式。
2. 接收实时帧并确认 Motive 没有录制。
3. 通过 SSH 确认默认 `remote` 根目录存在（不存在则创建），复用该目录，不创建会话子目录；检查本次目标文件不存在。
4. 设置并查询 Motive 当前保存目录，Take 名称使用北京时间 `YYYYMMDD_HHMMSS_ffffff`（含微秒），直接保存 `<时间点>.tak`，与本地 session_id 通过清单关联。
5. 默认启动 EGO、Windows 四时间戳探针。
6. 请求 Motive 开始录制，等待新的 NatNet 帧确认 recording 状态，再启动 EGO。
7. 停止 EGO，保留动捕尾段，停止 Motive 并等待新的非录制状态帧。
8. 在 Windows 只检查本次指定的 `<时间点>.tak` 文件（忽略同目录的历史 Take）：非空、大小及修改时间稳定、可独占读取，计算 SHA-256；随后导出 EGO。

原生 Take 留在 Windows，不自动复制到 Ubuntu，也不自动导出 C3D。启动前再次检查同名文件，拒绝覆盖；保存后严格核验本次指定文件，Motive 若自行改名会报核验失败，不会误认历史文件。

## 共用操作与前提

看到“正在录制”后开始动作。按一次 **Ctrl+C** 停止并保存，等待终端显示 `状态：complete`。定时停止使用 `--duration 60`。Take 模式的 complete 表示控制状态和文件保存检查通过，不表示已完成物理曝光标定或 Take 内容质量验证。

- EGO 连接 ADB 和 USB 网络，默认 IP `192.168.100.1`；多设备时加 `--ego-serial`。
- Motive 服务器默认 `169.254.213.247`；可用 `--motive-server-ip` 指定。NatNet 命令端口为 UDP 1510，网络和 Windows 防火墙须允许数据流及命令访问。
- `ssh windows-pc` 需免交互连接，可用 `--windows-host` 指定。H5 模式使用 SSH 探测 Windows 时钟；Take 模式还通过 SSH 创建目录及验证文件，因此即使传 `--no-clock-probes` 也需要 SSH。
- 当前版本两种模式均要求至少一个实时刚体可见，用来确认 NatNet 流已就绪。
- `pixi install` 安装依赖；`./mocap record --help` 查看参数。
- 不要在录制中从 Motive UI 或其他客户端另行切换 Take、目录或录制状态。NatNet 录制命令没有会话所有权令牌，本程序拒绝接管启动前已存在的录制，但不能排除运行中的外部控制竞争。
- 启动应答丢失时会尝试发送停止命令；停止最多尝试3次，每次均检查新状态帧；若停止状态不能确认，会明确记录失败，需现场检查 Motive。
- `--export-timeout 7200` 可增加 EGO 导出和 Windows Take 文件等待/哈希操作的超时。不要在保存阶段强制结束进程。

## 数据与记录

所有本地路径均相对于 `data/sessions/<session_id>/`：

| 路径 / 清单字段 | 内容 |
|---|---|
| `ego.h5、video/、capture/ego_export/` | 两模式共有的 EGO 原始导出 |
| `mocap.h5` | 仅 H5 模式生成 |
| `clocks/{ego,windows}.jsonl` | 默认保留的四时间戳探针 |
| `capture/events.jsonl` | 采集事件与 Ubuntu 单调时钟打点 |
| `capture/ego_control.json` | EGO 控制记录 |
| `capture/motive_control.json` | 仅 Take 模式的 NatNet 命令记录及错误 |
| `session.json → capture_mode` | 本次采用的模式 |
| `session.json → assets` | 本地资产及哈希 |
| `session.json → remote_assets.motive_take` | Windows 主机、实际 Take 路径、大小、SHA-256 |

EGO 原始文件仍保留在设备 SD 卡；如设备导出需要解密，沿用已有设备端流程，不将密钥复制到 Ubuntu。

两种模式都是软件协调录制，不保证硬件同时曝光。保留原始时间戳，不插值、不修改曝光。现有离线 `joint_capture.alignment` 和对齐 H5 导出器需要 `mocap_h5` 输入，**不能直接读取 Windows Take**；Take 路线需后续完成导出和时间轴关联，不能把现有 H5 对齐命令直接套用。
