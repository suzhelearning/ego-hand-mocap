# EGO 与 Ubuntu 动捕联合 H5 采集

在项目目录运行：

```bash
cd /home/current/syz/ego_hand_ground_truth
./mocap record
```

看到“正在录制”后开始动作。按一次 **Ctrl+C** 停止两端录制；等待终端显示 `状态：complete`，此时设备数据已导出到 Ubuntu 并校验完成。

定时录制（例如 5 秒）：

```bash
./mocap record --duration 5
```

每次自动生成唯一会话名。也可指定名称和输出根目录：

```bash
./mocap record --duration 60 --session-id hand_trial_001 --output-root /home/current/syz/ego_hand_ground_truth
```

已有同名文件会拒绝覆盖。默认保存位置：

| 数据 | 路径 | 内容 |
|---|---|---|
| EGO | `data/sessions/<会话名>/raw/ego/` | 设备原始 H5、视频和元数据，保留设备导出文件名 |
| Ubuntu 动捕 | `data/sessions/<会话名>/raw/mocap/natnet.h5` | NatNet 原始帧、刚体位置/姿态/有效性、PC接收时间、Motive时间及原始时钟计数 |
| 会话结果 | `data/sessions/<会话名>/session.json` | 状态、错误、设备记录身份、资产相对路径与哈希 |
| 对时依据 | `data/sessions/<会话名>/raw/clocks/{ego,windows}.jsonl` | 录制前后及录制中的双向四时间戳探针，用于后续离线时钟映射 |
| 操作记录 | `data/sessions/<会话名>/capture/` | Ubuntu单调时钟事件及设备控制响应 |

程序先检查数据与对时通道，开启 Ubuntu 动捕保存，再立即请求 EGO 开始录制；结束时先停 EGO，再保留少量动捕尾帧。因此动捕文件通常比指定时长略长，给 RGB 留出覆盖区间。**这是一次命令协调两端录制，不是硬件同时曝光。** 原始时间戳不改写、不插值，也不在采集阶段自动计算最终配对；离线映射到 PC 时间后，再按 RGB 时刻选择最近的动捕帧。曝光物理相位尚未标定。

## 运行前提

- EGO 连接 ADB 和 USB 网络，默认 IP `192.168.100.1`；多台设备时加 `--ego-serial <序列号>`。
- Motive 已打开，NatNet 数据流启用且至少一个刚体可见；默认服务器 `169.254.213.247`。
- `ssh windows-pc` 已配置免交互连接；用来记录 Windows 高精度时钟与 Ubuntu 的映射依据。
- 当前项目依赖已安装；新环境先执行 `pixi install`。`./mocap record --help` 查看参数。
- 录制期间由此命令统一控制 EGO，避免同时通过网页或其他程序切换录制。

程序不会接管已在录制的 EGO，也不修改曝光参数。中途掉流、EGO提前停止或录制被外部替换会报告失败并保留已有数据。读取完整结果以 `session.json` 为准，不能只凭某个 H5 文件存在判断采集成功。

离线配对默认保存到该会话的 `runs/<run_id>/sync/`。原始录制完成后追加的 Motive take/C3D，应先确认会话归属，再归档到 `raw/mocap/motive/`；联合采集命令不会自动录制或配对 C3D。

EGO 原始文件保留在设备 SD 卡。如果设备默认加密，使用设备已有解锁密钥在 SD 临时目录解密，复制到 Ubuntu 并逐文件核对 SHA-256 后清理临时副本；密钥不复制到 Ubuntu。长录制可用 `--export-timeout 7200` 增大解密和复制等待时间，设备及 Ubuntu 需要足够空间。不要在显示“正在保存”时强行结束进程。

`--no-clock-probes` 仅供明确不需要对时依据的排查录制，正式同步采集保留默认对时。
