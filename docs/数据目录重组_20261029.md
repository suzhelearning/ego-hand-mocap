# 数据目录重组记录（2026-10-29）

## 当前规则

一次采集对应一个 `session_id`；同一采集的原始数据和之后的离线结果都放在：

```text
data/sessions/<session_id>/
├── session.json
├── raw/
│   ├── ego/       # EGO H5、视频及设备元数据
│   ├── mocap/     # NatNet刚体H5、已确认属于本会话的Motive文件
│   └── clocks/    # EGO和Windows时钟探针
├── capture/       # 会话源清单、事件、控制响应及历史备份
└── runs/<run_id>/
    ├── run.json
    ├── ego/
    ├── mocap/
    ├── sync/
    ├── aligned/
    ├── evaluation/
    ├── logs/
    └── work/
```

`session.json`记录采集状态、错误及设备信息；`assets`用会话内相对路径和SHA-256定位本地原始文件。为兼容旧采集记录而保留的原始路径映射放在 `legacy_paths`，完整旧清单保存在 `capture/session.source.json`。来源不明的数据位于 `data/unassigned/`，测试数据位于 `data/samples/`。

每次离线运行有独立run ID。新的时钟配对命令为：

```bash
.pixi/envs/default/bin/python -m joint_capture.alignment <session_id>
```

命令创建 `runs/<run_id>/sync/` 和 `run.json`；可用 `--run-id <run_id>`指定 ID。旧布局会话须显式提供 `--output`。对齐 H5 导出工具通过 `--run-id`明确使用哪个运行，不会隐式选择“最新结果”。

可视化命令仍为 `./mocap visualize`。它从会话中发现已对齐 H5、原始NatNet刚体H5、未分配目录中的刚体样例和已生成的EGO手部motion JSON。当前尚无可显示的真实EGO手部21点结果；原始EGO传感器H5不会被当作手部轨迹。

## 有意保留的旧位置

`capture_sessions/`、`data/ego_data/`、`data/mocap_data/`、`data/aligned_h5/`、`data/ego_pose_h5/`、`data/mocap_c3d/`及`results/`仍保存原件，作为回退来源。正式采集和后续处理使用新会话布局。

`Third_Repo/`暂留原位：其OKVIS构建产物包含指向该绝对路径的CMake文件。移动会导致现有构建目录指向失效源文件；迁移不需要修改外部源码，故保留原路径。Zenoh ACL的新位置是 `deploy/zenoh/zenohd_acl.yaml`；`config/zenohd_acl.yaml`保留作旧配置副本。网络默认值位于 `configs/network/lab.json`。

迁移复制的对齐和位姿H5保持原字节，所以其中历史绝对源路径字段未重写。调用 `joint_capture.manifests.resolve_hdf5_reference()` 时，会根据所属session/run清单映射到新目录中的源文件；新导出的对齐H5使用会话相对路径。

本次未删除任何旧源文件或生成构建文件，也没有执行自动化测试套件。

## 复查与修复（2026-10-29）

后续复查执行了完整测试套件，首次结果为125项通过、7项失败。检查确认并修复以下问题：

- 采集入口提前创建`raw/ego`，触发EGO导出器的防覆盖检查。现在由导出器创建目标目录。
- 配置快照直接访问可选的`export_timeout`，导致旧调用方缺字段时异常。恢复3600秒默认值。
- 新布局入口遗漏旧会话ID冲突检查。现在同时检查新旧会话目录，阻止同名采集。
- 将采集测试中的旧绝对路径断言更新为新会话内相对路径，并验证实际文件可读取。

验证结果：Python完整测试135项通过；前端时间轴测试2项通过。新增迁移测试覆盖首次迁移、幂等重跑、冲突不覆盖和中断续传。重新计算迁移计划内2309项的源文件和目标文件SHA-256，并校验76项会话资产，全部匹配。

本次验证使用模拟设备和临时目录，没有启动真实EGO/NatNet硬件采集；硬件端到端实录尚未在本轮验证。
