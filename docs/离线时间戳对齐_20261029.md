## 输出与解读

每个会话目录含RGB_left_nearest.csv、RGB_right_nearest.csv、clock_models.json、summary.json。CSV保留RGB索引/原始时间/PC时间、动捕H5索引/帧号/曝光计数/PC时间、差值delta_ns（动捕减RGB）、覆盖和外推标记、各刚体跟踪有效性。利用mocap_index可直接索引原动捕H5中的刚体位置及姿态，不合成新姿态。

原始failed会话状态及错误保持不变并写入summary。两段用户录制分别有10、12个左RGB尾帧需要外推；建议初次评估仅选within_mocap_coverage=True、clock_extrapolated=False且目标刚体tracking_valid=True的行。

表中时间差是所选两帧映射时间的差值，不是同步精度或物理真值误差。拟合使用同一组探针，满足约束不是独立精度验证；origin_offset_interval_ns与rate_feasible_ppm为模型约束范围，尚未逐帧证明在所有可行模型下最近邻选择都不变。RGB曝光物理相位仍未标定，因此physical_exposure_alignment_valid全部为False。C3D格式样例不是同次采集，不参与本次配对。

## 再次运行

```bash
cd /home/current/syz/ego_hand_ground_truth
.pixi/envs/default/bin/python -m joint_capture.alignment \
  capture_sessions/<会话名> \
  --output results/alignment/<会话名>
```

输出目录必须不存在，防止覆盖既有结果。默认使用项目迁移后session.json里的真实H5路径。

### 会话目录更新（2026-10-29）

新会话的对齐命令接受会话 ID 并自动创建独立运行目录：

```bash
.pixi/envs/default/bin/python -m joint_capture.alignment <session_id>
```

配对文件位于 `data/sessions/<session_id>/runs/<run_id>/sync/`，运行状态写入同级 `run.json`。也可指定 `--run-id <run_id>`。旧布局路径继续可通过显式 `--output` 读取；历史报告和原有结果目录保持原样。

验证：对5个会话左右RGB全部结果，逐行使用全量动捕时间戳暴力argmin交叉检查，均与输出索引一致。原始输入SHA-256记录在每份summary.json。
