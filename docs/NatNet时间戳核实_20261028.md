## 字段选择与修正

| 本项目字段 | 含义 | 对齐曝光中点的处理 |
| --- | --- | --- |
| `natnet_timing.stamp_camera_mid_exposure` | Windows 高精度时钟域中的曝光中点 | 本机每 tick 为 100 ns；无需额外曝光相位修正（0 ms） |
| `natnet_timing.stamp_data_received` | Motive 收到相机数据的时刻 | 每帧减去其与曝光中点的 tick 差 |
| `natnet_timing.stamp_transmit` | 数据处理完成、即将发送的时刻 | 每帧减去其与曝光中点的 tick 差 |
| `motive_timestamp` | SDK `fTimestamp`，软件启动以来的软件时间（秒） | 官方定义不足以证明与曝光中点同原点/同相位，不直接认定为曝光中点 |
| `publisher_received_time_ns` / `receiver_time_ns` | Linux 接收时刻 | 包含传输等延迟；须先建立时钟映射，不能直接和 Windows ticks 相减 |

本机曝光时间坐标可写为 `t_win_s = stamp_camera_mid_exposure / 10000000`，或整数 `t_win_ns = stamp_camera_mid_exposure * 100`。这是 Windows 时钟坐标，不是 Unix 时间，也不是 Ego/Linux 时钟。换到 Ego 时钟仍需估计 `t_ego = a * t_win + b`，本次未测定 a、b 或曝光时间戳的物理误差。0 ms 指字段语义上的额外修正，不代表硬件测量误差为零。

### “曝光中点”具体指什么

OptiTrack 光学动捕通过相机观察标记点，再重建三维位置、解算刚体姿态。`CameraMidExposureTimestamp` 指动捕相机曝光窗口的中点；姿态是在后续计算阶段产生，但这个字段提供该帧观测的时间参考。

2026-10-28 再次通过 SSH 检查 Windows：

- 官方 SDK `C:\optitrack\NatNetSDK\Samples\SampleClient\SampleClient.cpp:920` 明确将该字段定义为相机曝光窗口中点。
- 保存的配置 `C:\ProgramData\OptiTrack\Motive\MotiveProfile.motive` 中发现多处 `CameraNodeCameraExposure` 值为 `100`。仅证明保存配置存在曝光参数；尚未核实当前在线相机型号、该值的单位及实时生效值，不能直接宣称当前曝光时间为 100 μs。

此前“真实物体姿态 → 曝光中点”的画法容易引起误解。曝光中点是观测的时间参考，不表示已独立验证解算姿态严格等于物体在该瞬间的真实姿态，也没有测量从某个真实运动事件到曝光中点的延迟。

本次测试测得的是由 NatNet 字段计算的相机曝光中点至 Windows 接收/发送延迟。尚未测定 Windows 到本机单向延迟、完整物理运动到本机的端到端延迟，以及姿态解算相对真实运动的时间误差。Windows ticks 与 Linux 单调时间必须先建立时钟映射，不能直接相减。
