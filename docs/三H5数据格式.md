# 三类 H5 数据组织

每个会话位于 `data/sessions/<session_id>/`。原始数据与后处理共存，三类文件各有职责；只创建有实际内容的文件。

| 文件 | 原始数据 | 内部处理版本 |
| --- | --- | --- |
| `ego.h5` | 保留设备原始 key、时间戳、IMU及元信息 | `processing/vision/<version>`、`processing/okvis/<version>` |
| `mocap.h5` | NatNet原有 `frames`、`rigid_bodies`；新采集还有 `raw` 硬链接。C3D为 `raw/markers`、`raw/frames` | `processing/mano/<version>` |
| `aligned.h5` | 不复制整份原始传感器文件 | `processing/sync/<version>`、`processing/alignment/<version>`；空间变换和评估待接入 |

视频保存在 `video/`；标注原件为 `labeled.c3d`；时钟探针在 `clocks/`；采集日志及原始导出元信息在 `capture/`。Take 留在 Windows `~/Desktop/syz/ego-hand/remote/<时间点>.tak`。

## 按 Stage 使用

在项目根目录执行，以下 `SESSION`、`VERSION` 和外部输入路径需替换为实际值：

```bash
# Stage 1：采集，默认 take；实时刚体方案显式选 h5
./mocap record
./mocap record --mode h5

# Stage 2：安装可选C3D解析依赖，并导入Label后的文件
.pixi/envs/default/bin/python -m pip install -e '.[c3d]'
.pixi/envs/default/bin/python tools/import_session_data.py c3d \
  --session-dir data/sessions/SESSION --source /path/to/labeled.c3d

# Stage 3：算法在外部执行，结果写回对应原始H5
.pixi/envs/default/bin/python tools/import_session_data.py mano \
  --session-dir data/sessions/SESSION --source /path/to/mano.npz \
  --mesh /path/to/mesh.npz --quality-json /path/to/quality.json \
  --version VERSION --units m --coordinate-frame mocap_world
# 视觉结果使用相同命令接口，把 mano 改为 vision，明确实际单位与坐标系。
.pixi/envs/default/bin/python tools/okvis_pose_to_h5.py \
  /path/to/okvis_run data/sessions/SESSION --version VERSION

# Stage 4：当前只支持具有曝光时钟与探针的NatNet数据
.pixi/envs/default/bin/python -m joint_capture.alignment SESSION --version VERSION
.pixi/envs/default/bin/python tools/export_aligned_h5.py SESSION --version VERSION

# Stage 6：已有刚体/marker/对齐结果预览
.pixi/envs/default/bin/python -m motion_web
```

C3D保存 `positions(F,M,3)`、`valid(F,M)`、残差和marker标签。坐标保留来源单位；无效点为NaN。`raw/frames/time_s` 仅相对C3D首帧，不能当绝对时间。MANO/视觉NPZ中的数值数组写入 `arrays/`，安全字符串写入 `parameters/`；对象数组默认跳过并记录，显式选取对象数组会报错，不启用pickle。网格写入 `mesh/{vertices,faces}`。视觉推理代码和统一21点接口仍待接通。

同步版本保存时钟模型、摘要及 `cameras/<camera>` 配对列；alignment版本保存按配对索引取出的刚体与可用性掩码。根目录快捷key指向最近发布的结果，但读取多版本时需显式指定版本，播放器列出可选版本。最近邻不插值；时钟配对不等同于RGB曝光相位标定。

## 写入与历史迁移

`processing/<stage>/<version>` 的版本名不可重复；写入在共享文件锁下通过临时副本完成再替换，更新 `session.json` 的当前文件哈希并保留初始哈希。写入时需要额外空间容纳H5副本。算法结果写入要求已有对应原始H5。`complete` 表示版本发布完成；历史源状态另以 `source_complete` 保存，不能据此把失败采集视为成功。

历史迁移工具默认只生成计划；`--apply` 才执行：

```bash
.pixi/envs/default/bin/python tools/flatten_session_data.py
.pixi/envs/default/bin/python tools/flatten_session_data.py --apply
```

原始文件按内容校验后移动；旧 `runs` 的H5按数据及属性校验后归入对应内部版本，CSV、JSON、配置等保留原始字节。迁移前清单保存在 `capture/session.before_flatten.json`。报告位于 `reports/flatten/`。历史文档描述的 `raw/`、`runs/` 不再是新采集默认路径。
