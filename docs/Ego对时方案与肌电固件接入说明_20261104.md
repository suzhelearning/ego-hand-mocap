# Ego 实际对时方案与肌电固件接入说明

日期：2026-11-04

目的：为肌电增加与现有 Ego 等价的对时应答能力，复用电脑端时钟映射方法。本文基于当前项目代码核对；肌电接口属于待实现要求，不表示当前固件已支持。

## 1. 核心结论

Ego 不修改自身时钟，也不覆盖传感器原始时间戳。电脑持续进行四时间戳交互，保存证据，离线计算“设备时间 → Ubuntu PC 单调时间”的映射，同时估计偏移和走速差。

肌电固件只需要接收带编号的请求，返回设备收到和回复的两个时间戳。电脑负责另外两个时间戳、拟合和数据换算。

现有算法不是简单的“往返延迟除以 2”。它使用通信因果关系约束映射，不强制假设去程和回程耗时相同。

## 2. 四个时间戳

| 符号 | 事件 | 使用的时钟 |
|---|---|---|
| h1 | 电脑发送请求前 | PC CLOCK_MONOTONIC |
| d1 | 设备完整收到请求后 | 设备单调时钟 |
| d2 | 设备准备回复时 | 与 d1 相同的设备单调时钟 |
| h2 | 电脑完整收到回复后 | 与 h1 相同的 PC 单调时钟 |

交互过程：

```text
电脑                                    设备
记录 h1 → 发送请求编号 ----------------→ 完整收到请求，记录 d1
                                        记录 d2，生成回复
记录 h2 ← 完整收到回复 ←---------------- 请求编号、d1、d2
```

h1/h2 不能使用浏览器时间或写盘时间；设备 d1/d2 与传感器时间戳必须来自同一时钟域。

## 3. Ego 当前如何实现

### 3.1 连接和数据格式

电脑在可达网卡上创建临时 TCP 监听端口，通过 ADB 启动 Ego 端 Python 探针。Ego 主动连接电脑，双端启用 TCP_NODELAY。ADB 用于启动进程；实际对时消息通过 TCP 网络连接传输，现场可使用 USB 网络。

连接建立后，Ego 首先发送一行：

```text
<本次连接随机令牌> 1000000000\n
```

第二项是设备时钟频率，单位 ticks/s。电脑验证令牌、来源 IP 和频率。

每次请求是一行十进制编号：

```text
7\n
```

对应回复：

```text
7 <d1> <d2>\n
```

Ego 的 d1、d2 来自 Python `time.monotonic_ns()`，单位纳秒。

### 3.2 真实打点位置

电脑端等价逻辑：

```python
h1 = time.monotonic_ns()
connection.sendall(f"{index}\n".encode())
reply = stream.readline(256)
h2 = time.monotonic_ns()
# 解析 reply，核对回复编号和设备时间顺序
```

Ego 端等价逻辑：

```python
request = stream.readline()
d1 = time.monotonic_ns()
index = int(request)
d2 = time.monotonic_ns()
connection.sendall(f"{index} {d1} {d2}\n".encode())
```

因此这里是应用层时间戳，不是网卡硬件收发时间：d1 包含收到完整请求前的传输与调度；d2 后面仍有编码、发送及排队。算法将这些时间包含在通信边界里，不能宣称已逐项测出或消除。

每次完成交互后等待约 0.2 秒再请求，故频率约 5 Hz，并非严格定时 5 Hz。整个录制期间持续保存对时样本。

### 3.3 保存字段

每次交换保存：

```json
{
  "index": 7,
  "pc_send_ns": 1000000000,
  "remote_receive_ticks": 900000000,
  "remote_send_ticks": 900010000,
  "pc_receive_ns": 1000200000
}
```

上述数值仅为字段示例，不是实测结果。文件元数据保存设备时钟频率及 PC 时间域。现有采集会话还通过其他设备接口取得并保存 Ego boot_id，离线对齐时核对；boot_id 并不是现有 Ego 每条 TCP 应答内的字段。

## 4. 电脑端怎样计算映射

为方便理解，以下所有时间统一换成秒。定义：

```text
F(d) = a × (d − d0) + b
```

- F(d)：设备时刻 d 对应的 PC 时间。
- d0：选取的设备参考时刻，用于改善数值稳定性。
- a：设备时间到 PC 时间的速率比例，接近 1。
- b：设备参考时刻 d0 对应的 PC 时间。

每次交互满足两条因果关系：

```text
h1 ≤ F(d1)     # 电脑先发，设备后收
F(d2) ≤ h2     # 设备先回，电脑后收
```

电脑收集多次交互，用所有这些不等式求出允许的 a、b 范围，并选择范围内的映射参数。这样既估计偏移，也考虑长时间时钟走速差。

若暂时忽略走速差，写作 F(d)=d+偏移，则一次交互给出：

```text
h1 − d1 ≤ 偏移 ≤ h2 − d2
```

这个范围的宽度为：

```text
(h2 − h1) − (d2 − d1)
```

它对应扣除设备内部处理时间后的往返耗时。往返越短，单次约束通常越紧。无需将其除以 2，也无需先假设双向延迟相等。

### 当前实现细节

`fit_clock()` 把设备 ticks 按频率换算到纳秒，以中间样本的设备接收时间作为参考原点，通过 SciPy `linprog` 求解偏移修正和速率修正的可行范围。

它分别求参考原点处最小、最大偏移对应的可行参数解，取这两个参数解的平均作为最终点估计；同时计算可行速率范围。这个选择不是对真实时钟差的无偏保证。

至少需要 4 个样本；约束不可行、无界或时间顺序非法时会报错。保存内容包括拟合参数、可行区间、样本数量、频率、最大约束违反量和探针有效时间段。对齐阶段标记探针区间外的外推。

设备重启、参考 PC 重启或时钟域改变后，旧映射不能直接复用。原始设备时间始终保留，映射后的 PC 时间另外保存。

## 5. 肌电固件需要实现什么

以下是肌电新增接口要求，不要求照搬 Ego 的 TCP 文本传输。肌电继续使用现有 USB 二进制协议即可。

### 5.1 请求与回复

请求至少包含：

| 字段 | 要求 |
|---|---|
| request_id | 用于唯一匹配本连接内的请求与应答，建议 uint32 |

回复至少包含：

| 字段 | 要求 |
|---|---|
| request_id | 原样回显 |
| device_receive_us | 完整收到并识别对时请求时的设备单调时间，建议 uint64 |
| device_send_us | 准备回复、进入发送路径前的同源设备单调时间，建议 uint64 |
| status | 是否处理成功；非法请求不能作为有效对时样本 |

建议通过连接握手或回复额外提供：

- boot_id：每次设备启动变化，用于识别重启，不能只用固定 USB 序列号替代。
- 时钟单位或 frequency_hz：若明确使用微秒计数，则固定为 1000000 ticks/s。
- 固件版本、构建标识和设备身份，便于核对能力。

不必让固件计算偏移，不必修改设备时钟，也不要求固件返回电脑 h1：电脑可按 request_id 保存并查回。若复用已有含 h1 回显的命令格式，可保留该字段。

具体 type/opcode、字节偏移、长度、CRC 和错误应答由固件方给出明确协议及测试向量；不能仅保留类型枚举而不实现命令读取和应答。

### 5.2 打点与采样要求

1. 设备收到完整请求时尽早记录 d1，回复进入发送路径前尽晚记录 d2；明确真实打点位置以及 d2 后还有哪些队列。
2. d1、d2 与 EMG 原始时间戳使用同一个单调计时源，单位和回绕规则明确。
3. 建议对时和采样都采用完整 64 位时间；若采样帧仍为 32 位，必须提供与 64 位对时时间一致的回绕历元关联方式，不能将两者分别清零后混用。
4. 正常采样期间允许持续对时，不暂停 ADC/IMU、不清空队列、不重置序号，不更改原始采样时间。
5. 如果应答进入与 EMG 共用的发送队列，说明排队位置；尽量降低可避免的等待，并记录新增对时负载是否影响采样。
6. 明确 EMG、IMU 时间戳相对真实采样事件的位置。现有 v1 文档称 EMG 在采集任务读取入口打点、IMU 在 UART 接收解析后打点，这些采样内部延迟不会被时钟映射自动修正。

### 5.3 电脑端接入

电脑在写对时请求前记录 h1；完整回复字节读到后、业务处理及写盘前记录 h2。核对 request_id、CRC、status、boot_id 和 d2≥d1，转换为现有四时间戳保存字段。

每只手环独立连接、独立保存样本、独立计算映射。先沿用 Ego 每轮结束后间隔约 200 ms 的请求节奏，再依据实测通信负载调整。无须固定每轮 8 次才能使用当前 Ego 算法；若固件协议规定批次大小，主机按协议组织批次并保存每次有效交换。

## 6. 联调验收

- 两只设备均能在持续采样时返回匹配的应答，记录请求数、成功数、超时和错误。
- 检查四时间戳的本机/设备内先后顺序，保留完整原始交换记录。
- 比较加入对时前后的采样率、CRC、序号缺口和固件丢弃计数。
- 在覆盖录制开始、中间、结束的探针上拟合映射，检查可行区间、漂移及独立留出样本的兼容性。
- 验证重启、断连重连和时间回绕后不会沿用错误映射。
- 时钟约束通过不等于真实采样同步精度通过。需要独立共同事件验证采样链路延迟后，才能声明具体毫秒精度；Ego 的图像曝光相位也是独立问题。
